Code map: every folder and module

A guided walk through the repository. For each file: what it is for, what it exports, and who uses it. About 8,000 lines of TypeScript, HTML, CSS and SQL in total.

The folders

jira-bug-dashboard/
├── public/              the web page: HTML, CSS, icon, these Learn guides (served as-is)
├── src/
│   ├── client/          frontend TypeScript (runs in the browser)
│   ├── server/          Local edition backend (Node.js)
│   ├── core/            Jira logic shared by both backends (no Node, no Cloudflare APIs)
│   └── shared/          TypeScript types shared by everyone
├── scripts/             build the demo site, mock Jira, local tests
├── cloud/               Cloud edition (its own package.json)
│   ├── src/             the Cloudflare Worker
│   ├── public/          files only the cloud needs: sw.js, _headers, privacy page
│   ├── migrations/      D1 schema (numbered SQL files)
│   ├── scripts/         mocks, tests, key generation, asset build
│   └── wrangler.jsonc   Cloudflare configuration (dev + production)
├── .github/workflows/   GitHub Actions: deploy the demo to Pages
├── package.json         Local edition: build + start
└── tsconfig.json        TypeScript settings for src/

How code becomes something that runs

  • Local edition: tsc compiles src/ to dist/; Node runs dist/server/index.js, which serves public/ and dist/client/.
  • Demo: the same compile, then build-site.mjs copies files into site/; GitHub Actions publishes it.
  • Cloud: the same compile for the frontend; Wrangler's bundler (esbuild) bundles cloud/src/index.ts together with src/core into one Worker script; build-assets.mjs prepares the static files; wrangler deploy uploads both.
