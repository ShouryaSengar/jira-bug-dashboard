How to add a feature

A worked example: making JARVIS announce when a bug's due date changes. It touches every layer, so it is a map of where things go.

⏱ 9 min readGuide 46 of 47

1. Decide where each part lives

PartFile
Event type namesrc/shared/types.ts (JarvisEventType)
Detection (from the changelog)src/core/detect.ts (classifyChanges, IMPORTANCE)
Words and notification textsrc/client/jarvis-core.ts (templates, EVENT_LABEL, notificationFor, describeEvent)
Labels in history and For Yousrc/core/detect.ts (eventLabel), src/client/jarvis.ts (badge colour)
Server-side push rulesnothing to do: event types are validated against EVENT_TYPES automatically
Testsmocks (mock-jira.mjs, mock-atlassian.mjs) + suites

2. Type

// src/shared/types.ts
export type JarvisEventType = 'assigned' | … | 'updated' | 'due';

TypeScript will now point at every place that must handle the new value (records keyed by event type will fail to compile until filled in). That is the main benefit of strict types.

3. Detection

// src/core/detect.ts, inside the loop over changelog items
} else if (fid === 'duedate') {
  out.push(draft(c.siteUrl, i, 'due', { occurredAt, actor, actorId, from, to, own }));
}
// and in IMPORTANCE:  due: 'normal'

4. Words

// src/client/jarvis-core.ts
due: [
  (c) => `${c.pre}the due date of ${c.k} moved to ${c.to}.`,
  (c) => `${c.k} has a new deadline${c.post}: ${c.to}.`,
],
// EVENT_LABEL: due: 'Due date change'
// notificationFor: case 'due': return { title: `${e.key}: due ${e.to ?? 'removed'}`, body: e.summary };

5. Test it

  1. Add a control to the mock: case 'due': hist(i, BOB, [{ field: 'duedate', fieldId: 'duedate', fromString: …, toString: a.to }]).
  2. Add a step to test-jarvis.mjs and test-e2e.mjs: await step('due date change', () => mock('due', {key: 'ABC-2', to: '2026-12-01'}), 'due:ABC-2').
  3. Add a template test to test-core.mjs.
  4. Run all suites (both editions use the core).

6. Ship it

git checkout -b feature/due-date-events
git add -p                       # review each change
git commit -m "JARVIS: announce due date changes"
npm run build && (cd cloud && npm run deploy:dry)
# after review: merge, push, cloud: npm run deploy

General rules for changes

  • Shared logic goes in src/core (no Node or Cloudflare APIs), so both editions get it.
  • Keep the API contract: if the Local server and the Worker both serve an endpoint, change both and the shared type.
  • Mind the free tier in the cloud: every new Jira call in the monitor costs subrequests for every user, every interval.
  • Database changes = a new migration file, additive.
  • Escape everything you render (esc()), validate everything you receive.
  • Update these guides when behaviour changes.
