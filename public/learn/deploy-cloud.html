Deploy the Cloud edition, step by step

The exact path used to put this app on Cloudflare for free, in order, including every surprise along the way. Follow it top to bottom and you will have your own instance.

⏱ 16 min readGuide 40 of 47
Time and costAbout 45 minutes the first time. Cost: zero (Cloudflare Workers Free, D1 Free, Atlassian developer console). You need a Cloudflare account and an Atlassian account.

The plan

1. Prepare

git clone https://github.com/ShouryaSengar/jira-bug-dashboard.git
cd jira-bug-dashboard
npm install                       # root: TypeScript for the shared frontend
cd cloud && npm install           # Cloud: wrangler + workers types (kept separate from the Local edition)

Optional but recommended: run it locally against the mock first (no accounts needed): see How this app is tested.

2. Log Wrangler in to Cloudflare

npx wrangler login                 # or: npx wrangler login --browser=false
npx wrangler whoami                # shows your account name and id
What went wrong for usThe first link opened in the default browser (Edge) while we approved in another (Brave): Cloudflare answered "No CSRF value available in the session cookie". A stale tab then sent an old state ("query string parameter doesn't match"). Fix: --browser=false, open the printed link in the browser you are signed in with, approve once, close old tabs.

3. Create the database

npx wrangler d1 create jbd-cloud

Copy the printed database_id into cloud/wrangler.jsonc under env.production.d1_databases, keeping "binding": "DB". (Wrangler offers to add it itself with a different binding name; decline.) Then create the tables:

npm run build                                                   # shared frontend + dist-assets
npx wrangler d1 migrations apply DB --remote --env production   # 0001, 0002…

4. First deploy, to get your URL

npx wrangler deploy --env production
workers.dev subdomainA new account must have a workers.dev subdomain. Wrangler asks interactively; in a non-interactive shell it fails and prints a dashboard link (which for us was a 404, the dashboard had moved). Check whether you already have one: curl -H "Authorization: Bearer $TOKEN" https://api.cloudflare.com/client/v4/accounts/<account-id>/workers/subdomain, or in the dashboard under Workers & Pages. Ours already existed (shouryacode2021).

Your URL is https://jira-bug-dashboard-cloud.<subdomain>.workers.dev. Put it in env.production.vars.APP_ORIGIN. Until configuration is complete, /api/config answers 503 "not configured: missing …" and the page falls back to demo mode. That is intended.

5. Keys and secrets

node scripts/set-prod-secrets.mjs mailto:you@example.com

This one script generates a VAPID key pair and a 32-byte token-encryption key in memory, pipes TOKEN_ENC_KEY, VAPID_PRIVATE_KEY and VAPID_SUBJECT straight into wrangler secret put, and writes only the public key into wrangler.jsonc. Check with npx wrangler secret list --env production (names only). Redeploy afterwards.

Run it onceRunning it again replaces the keys: existing push subscriptions stop working and every user must sign in again.

6. Register the Atlassian app

At developer.atlassian.com/console/myapps: Create → OAuth 2.0 integration; Permissions: Jira API classic scopes read:jira-work, read:jira-user, and User identity API; Authorization: callback https://<your-url>/auth/callback, resource-level. Full details: The developer console.

7. Client id and secret

  • Client ID (public): into env.production.vars.ATLASSIAN_CLIENT_ID.
  • Secret: type it yourself, it never goes into a file: 
    npx wrangler secret put ATLASSIAN_CLIENT_SECRET --env production

8. Deploy and sign in

npx wrangler deploy --env production
curl https://<your-url>/api/config          # {"edition":"cloud","configured":false,"signedIn":false,…}
npx wrangler tail --env production --format pretty   # watch while you sign in

Open the URL, Sign in with Atlassian, choose your site, Accept. You should land on For You. In the tail you will see /auth/login → /auth/callback → /api/mine, and within five minutes a cron line with "checked": 1 (your baseline). Verify at rest (read-only):

npx wrangler d1 execute DB --remote --env production --command \
  "SELECT (SELECT COUNT(*) FROM users) users, (SELECT status FROM oauth_grants) grant_status"

9. Share with others

Set the app's Distribution to Sharing within organization or Sharing with anyone, add your privacy policy (https://<your-url>/privacy), declare that personal data is stored (the Personal Data Reporting API is implemented), and send colleagues the URL. Company admins may need to approve third-party apps.

Later deploys

cd cloud
npm run deploy        # = build + remote migrations + wrangler deploy

Adding a new migration file? It runs automatically on the next npm run deploy. Want to check first? npm run deploy:dry.

Checklist

  • ☐ wrangler whoami shows the right account
  • ☐ database_id set, migrations applied
  • ☐ APP_ORIGIN, ATLASSIAN_CLIENT_ID, VAPID_PUBLIC_KEY set (no REPLACE_ left)
  • ☐ 4 secrets listed: ATLASSIAN_CLIENT_SECRET, TOKEN_ENC_KEY, VAPID_PRIVATE_KEY, VAPID_SUBJECT
  • ☐ Callback URL in Atlassian matches exactly
  • ☐ /api/config returns 200 with "edition":"cloud"
  • ☐ Sign-in works; baseline appears in the tail
  • ☐ JARVIS → Enable notifications → Send a test push arrives
  • ☐ Privacy policy reachable; distribution set if sharing
