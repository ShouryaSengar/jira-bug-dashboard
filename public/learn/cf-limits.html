The free tier and capacity maths

What Cloudflare gives for free, which limit this app hits first, how many users fit, and what changes on the paid plan. Figures checked against Cloudflare's documentation in November 2026; check them again before relying on them.

⏱ 9 min readGuide 31 of 47

The free allowances

ProductFree limit
Worker requests100,000 per day (static assets free and unlimited)
Worker CPU10 ms per invocation
Subrequests50 per invocation (D1 included)
Cron triggers5 per account
D1 rows read5,000,000 per day
D1 rows written100,000 per day
D1 storage500 MB per database, 5 GB total, 10 databases
D1 queries50 per invocation

Sources: Workers limits, D1 limits, D1 pricing.

What happens at a limit

  • The free plan cannot charge you. Nothing upgrades automatically.
  • Daily request limit: error 1027 (or 429 for paths that always run the Worker) until 00:00 UTC.
  • CPU: error 1102 "Worker exceeded resource limits" for that invocation (occasional small overruns are tolerated).
  • D1 daily limits: queries return errors until the reset.
  • The monitor treats all of these as temporary failures: back off, keep the checkpoint, retry.

Counting one idle user check

CostAmount
Subrequests1 (the incremental search)
CPU~0.4 ms (parse a snapshot of 300 bugs and 3000 seen ids)
D1 writes0 (one heartbeat row every 20 minutes)

A user with one change and one device

Search 1 + changelog 1 + comments 1 + commit 1 + devices 1 + push 1 + mark delivered 1 = 7 subrequests; about 1.5 ms CPU; 2–3 rows written.

Which limit comes first?

LimitUsers per minute it allowsBinding?
50 subrequests~40 idle users (minus overhead)
10 ms CPU~12 users with a safety margin (some with changes)yes
100,000 writes/day~700–1000 users in total
100,000 requests/daycron uses 1,440; leaves ~98,000 for API calls

So runs are capped at MONITOR_MAX_USERS_PER_RUN = 12.

Capacity formula

users without delay  ≈  users_per_run × interval_minutes
                     =  12 × 5   =  60  (default)
                     =  12 × 10  = 120
                     =  12 × 15  = 180

Beyond that, users are deferred: they are checked a minute or two later than their slot. With 120 users at a 5-minute interval, the effective interval becomes about 10 minutes. Nothing is lost; it is just slower.

Daily API requests

A user opening the app makes roughly 5–10 Worker requests (config, status, events, mine, notify, a detail or two). 98,000 / 10 ≈ 9,800 app opens per day before the request limit matters.

Upgrading (only if you ever need it)

Workers Paid is a monthly subscription (check Cloudflare's current price). It raises CPU to 30 seconds per invocation by default, subrequests to 10,000, and D1 to billions of reads and tens of millions of writes per month included. For this app, raise MONITOR_MAX_USERS_PER_RUN (and optionally MONITOR_SUBREQUEST_BUDGET) after upgrading; nothing else changes.

Never upgrade by accidentUpgrading is a deliberate action in the Cloudflare dashboard. Neither Wrangler nor this app does it. If you do upgrade, set a spending limit in the dashboard.

Watching usage

  • Dashboard → Workers & Pages → your Worker → Metrics: requests, errors, CPU time (median and p99).
  • Dashboard → D1 → your database → Metrics: rows read and written per day.
  • Each cron log line shows the subrequests used ("subrequests": 5).
