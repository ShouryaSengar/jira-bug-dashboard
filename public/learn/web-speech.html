Speech, notifications and browser rules

The two browser features JARVIS relies on for talking to you, and the rules browsers impose to stop websites from being annoying.

⏱ 7 min readGuide 35 of 47

Speech synthesis

const u = new SpeechSynthesisUtterance('Sir, a quick update.');
u.voice = speechSynthesis.getVoices().find((v) => v.name.includes('Andrew'));
u.rate = 1; u.volume = 0.85; u.pitch = 0.95;
u.onend = () => nextInQueue();
speechSynthesis.speak(u);
  • Voices come from your system and browser, not from the website. Edge on Windows offers Microsoft "Natural" voices (Andrew, Guy…); macOS offers Daniel, Samantha; Chrome adds Google voices. The same page lists different voices in different browsers.
  • Voices load late: getVoices() may be empty at first; the voiceschanged event fires when they arrive (Edge's online voices take a moment).
  • Overlapping calls queue up in the browser, but some browsers cancel or drop lines; the app keeps its own queue and waits for end.
  • No speech from service workers: only pages can speak, so voice needs an open tab.

The autoplay rule

Chrome and Edge do not let a page produce sound until the user has interacted with it (a click or key press) at least once since loading. navigator.userActivation.hasBeenActive tells whether that happened. JARVIS holds announcements until then and shows "Click anywhere to enable voice" in the header. Lines that wait more than 2 minutes are dropped as stale.

Notifications

if (Notification.permission === 'default') await Notification.requestPermission();   // from a click!
const n = new Notification('ABC-1 was reopened', { body: 'Login fails on Safari', tag: 'jbd-ABC-1-reopened' });
n.onclick = () => { window.focus(); openIssue('ABC-1'); };
PermissionMeaningWhat to do
defaultnot asked yetask from a button click
grantedallowedshow notifications
deniedblockedcannot ask again from the page; the user must change site settings (padlock icon in the address bar)
  • tag replaces an older notification with the same tag instead of stacking.
  • requireInteraction: true keeps it until dismissed (used for high-importance events).
  • Android Chrome only allows notifications from a service worker (registration.showNotification), not new Notification().
  • Operating-system "Focus" or "Do not disturb" modes can hide them; that is outside the browser's control.

Several tabs

Each open tab runs its own copy of the page. Without coordination, three tabs would speak the same line three times. The app uses localStorage heartbeats and the Web Locks API (navigator.locks.request), which lets tabs of the same origin take a named lock one at a time, so exactly one tab claims each batch. Details in JARVIS: speech and notifications.

Testing these in automation

Headless browsers have no audio and often deny notifications. The browser tests replace speechSynthesis with a recorder (to assert exactly what would be said) and grant notification permission in a full (not "shell") Chromium build. Push delivery is simulated with the Chrome DevTools Protocol command ServiceWorker.deliverPushMessage.
