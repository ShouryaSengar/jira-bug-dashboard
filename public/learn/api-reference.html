API reference

Every HTTP endpoint of the backend, what it expects and what it returns. Both servers implement the shared ones with the same shapes; cloud-only endpoints are marked ☁️.

Conventions

  • All responses are JSON with security headers and Cache-Control: no-store.
  • Errors: {"error": "human readable message", "code": "machine_code"}. Codes: signin (401, not signed in), reauth (401, Jira access revoked or expired), rate_limited (429), not_configured (503), nosite (409).
  • Every POST/DELETE must send X-JBD: 1 and come from the app's own origin (CSRF protection). The frontend helper post() does this.
  • ☁️ Every endpoint except /api/config and /auth/* requires the session cookie. User ids are never accepted from the client.

Development only

POST /api/__dev/tick (run one cron tick and return its report) and POST /api/__dev/pdr (run the privacy report) exist only when ALLOW_INSECURE_PUSH = "1", which is set in the dev environment and never in production. Locally you can also trigger the real scheduled handler with curl "http://localhost:8787/__scheduled?cron=*+*+*+*+*".

Calling the API yourself

# signed-out config (works on the live site)
curl https://jira-bug-dashboard-cloud.shouryacode2021.workers.dev/api/config

# anything else needs your session cookie; easiest from the browser console on the site:
await (await fetch('/api/jarvis/status')).json()
await (await fetch('/api/jarvis/sync', { method: 'POST', headers: { 'X-JBD': '1' } })).json()
