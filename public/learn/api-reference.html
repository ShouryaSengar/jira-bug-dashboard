API reference

Every HTTP endpoint of the backend, what it expects and what it returns. Both servers implement the shared ones with the same shapes; cloud-only endpoints are marked ☁️.

⏱ 12 min readGuide 16 of 47

Conventions

  • All responses are JSON with security headers and Cache-Control: no-store.
  • Errors: {"error": "human readable message", "code": "machine_code"}. Codes: signin (401, not signed in), reauth (401, Jira access revoked or expired), rate_limited (429), not_configured (503), nosite (409).
  • Every POST/DELETE must send X-JBD: 1 and come from the app's own origin (CSRF protection). The frontend helper post() does this.
  • ☁️ Every endpoint except /api/config and /auth/* requires the session cookie. User ids are never accepted from the client.

Connection and configuration

Method and pathPurposeResponse
GET /api/configWhat the page needs to startLocal: {configured, source, jiraUrl, email, displayName, severityFields, issueTypes, configFile}. Cloud: also edition: "cloud", signedIn, needsReauth, user, site, sites[], vapidPublicKey, minIntervalMin
POST /api/configLocal: save {jiraUrl, email, apiToken, severityFields, issueTypes} (verified first). Cloud: update {activeCloudId, severityFields, issueTypes}updated config
DELETE /api/configLocal: delete credentials. Cloud: disconnect (delete tokens, sites, monitor state, devices, all sessions)config
☁️ GET /auth/loginStart sign-in (302 to Atlassian, sets state cookie)redirect
☁️ GET /auth/callback?code&stateFinish sign-in (302 to /?view=foryou&connected=1 or /?auth=<reason>)redirect
☁️ POST /auth/logoutEnd this session{ok: true}
☁️ POST /api/account/deleteBody {"confirm": "DELETE"}; erases every row for the user{deleted: true}

Sign-in failure reasons in ?auth=: state, denied, code, exchange, offline, scopes, profile, nosite.

Jira data

Method and pathPurposeResponse
GET /api/bugs?key=ABC-123Epics view: bugs linked to or under an issue{parent, bugs: Bug[], severityFieldsUsed, jql, fetchedAt}
GET /api/mineFor You: bugs assigned to me (cloud: max 300){me, bugs: MyBug[], jql, truncated, recentlyAssignedSource, fetchedAt}
GET /api/issue?key=ABC-123Detail drawerIssueDetail: summary, status, priority, severity, project, people, dates, parent, labels, description, comments[], history[], links[]

Keys must match ^[A-Z][A-Z0-9_]+-\d+$, otherwise 400.

☁️ Web Push

Method and pathPurpose
POST /api/push/subscribeBody = PushSubscription.toJSON() + label; endpoint must be an allowed push service; max 5 devices
POST /api/push/unsubscribe{endpoint} or {id}, only your own
GET /api/push/devices{devices: [{id, label, created_at, last_ok_at}]}
POST /api/push/testSend a test push to your devices (max 3 per minute); dead subscriptions are removed

Development only

POST /api/__dev/tick (run one cron tick and return its report) and POST /api/__dev/pdr (run the privacy report) exist only when ALLOW_INSECURE_PUSH = "1", which is set in the dev environment and never in production. Locally you can also trigger the real scheduled handler with curl "http://localhost:8787/__scheduled?cron=*+*+*+*+*".

Calling the API yourself

# signed-out config (works on the live site)
curl https://jira-bug-dashboard-cloud.shouryacode2021.workers.dev/api/config

# anything else needs your session cookie; easiest from the browser console on the site:
await (await fetch('/api/jarvis/status')).json()
await (await fetch('/api/jarvis/sync', { method: 'POST', headers: { 'X-JBD': '1' } })).json()
