Rendering: strings, escaped

Views are rendered by building HTML strings and assigning innerHTML. Every value that comes from Jira or the user goes through esc(), which replaces & < > " ' with entities, and every link through safeUrl(), which only allows http(s). Combined with the strict CSP (no inline scripts allowed), a malicious issue summary like <img onerror=…> is shown as text, never executed.

// util.ts
export const esc = (s: unknown): string => String(s ?? '').replace(/[&<>"']/g, (c) => ESC[c] ?? c);
export const safeUrl = (u: string): string => (/^https?:\/\//i.test(u) ? u : '#');

Rendering is split into small functions (renderHeader, renderCharts, renderTable…). A filter change calls only renderResults(), which redraws charts, chips and the table but not the header.

Events: delegation

Instead of attaching a listener to every row and chip, each container has one listener that looks at data-* attributes of the clicked element (data-sort, data-quick, data-group, data-fy-open…). This keeps working after re-rendering, because the container itself is never replaced.

$('thead').addEventListener('click', (e) => {
  const col = e.target.closest('[data-sort]')?.dataset.sort;
  if (col) setFilters(filters.sort === col ? { dir: -filters.dir } : { sort: col, dir: … });
});

Analysis: the numbers on screen

  • Age (ageMs): open bugs = now − created; closed bugs = resolved − created ("time to close").
  • Level (ageLevel): ok / warn / crit by your thresholds (default 3 and 7 days); done bugs are grey.
  • Stale: open and not updated for N days (default 5).
  • Changed (changeOf): compares each bug's updated to the baseline saved when you pressed "Mark all as seen".
  • Trend: per week (Monday-based), bugs created, resolved, and open at the end of the week, for up to 26 weeks.
  • Sorting: severity sorts by the number in "2 - Major"; age sorts closed bugs after open ones.

Charts without a library

charts.ts builds SVG and HTML strings:

  • Donut: one SVG <circle> per slice using stroke-dasharray (a circle of radius 15.9155 has a circumference of 100, so a slice of 23% is "23 77").
  • Bars: HTML buttons with a width percentage, so they are clickable and accessible.
  • Trend: an SVG with grid lines, paired bars and a path for the backlog line.

Colours come from CSS variables (var(--red) etc.), so charts follow the theme automatically.

Themes

<html data-theme="dark" data-accent="teal"> switches a block of CSS variables. boot.js sets these attributes before the page paints. The "system" theme follows the operating system with a prefers-color-scheme media query.

The For You view (foryou.ts)

  1. showForYou() shows a cached result immediately (if any), then refreshForYou() fetches api/mine.
  2. Filters (FyFilters) are saved; KPI tiles set a preset of filters; charts toggle values.
  3. Clicking a row opens the detail drawer: openIssueDetail(key) fetches api/issue?key=… and marks that bug's JARVIS events as read. The URL gets ?issue=KEY so notification clicks can deep-link.
  4. When JARVIS reports activity, onActivity() (debounced 2.5 s) refreshes the list quietly.

JARVIS in the browser (jarvis.ts)

  • Ingest: every event (from the stream, push, "check now", or a simulation) goes through ingest(), which de-duplicates by id, appends to history, and batches live events for 1.2 s (12 s in digest mode).
  • Flush: plan() from jarvis-core.ts decides notifications and speech; Speaker queues voice lines.
  • Several tabs: tabs write a heartbeat to localStorage; only one tab that is allowed to speak announces (Web Locks make the claim atomic).
  • Cloud: registers sw.js, listens to its messages, subscribes to Web Push on request, and syncs notification rules to the server.

Rules and templates: JARVIS: speech and notifications.

Responsive layout

Below 760 px wide: the header wraps; KPI grids go to three columns; the bug table becomes a list of cards (each <td> shows its data-label as a caption); the filter drawer becomes a bottom sheet; dialogs dock to the bottom. No JavaScript is involved: it is all CSS media queries.
