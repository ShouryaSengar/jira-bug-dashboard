How this app is tested

The test strategy: fake versions of every outside service, end-to-end tests against the real runtime, browser tests, unit tests, regression checks against a real Jira, and CPU measurements. About 200 automated checks in total.

The idea: replace the outside world with mocks

Real Atlassian, real Jira and real push services cannot be scripted ("now reopen ABC-1"), cost real accounts, and are slow. So each is replaced by a small fake server that behaves like the documented API and can be controlled by the tests.

Running them

# Local edition
node scripts/mock-jira.mjs &
JBD_CONFIG_DIR=$(mktemp -d) PORT=4800 JIRA_URL=http://127.0.0.1:4700 JIRA_USERNAME=me@x.com JIRA_API_TOKEN=x node dist/server/index.js &
node scripts/test-jarvis.mjs
node scripts/test-core.mjs

# Cloud edition (in cloud/)
node scripts/gen-vapid.mjs --dev
npm run build && npm run db:migrate:local
node scripts/mock-atlassian.mjs &
sh scripts/dev-server.sh &
node scripts/test-unit.mjs
node scripts/test-e2e.mjs
PLAYWRIGHT=/path/to/playwright/index.mjs node scripts/test-ui.mjs
Start from a clean stateThe suites assume fresh mocks and an empty local database (the e2e suite empties it itself). A second run against a mock that already has changes will report failures that are not real. We hit this twice; the fix is to restart the mock.

Techniques worth borrowing

  • A cookie jar in 20 lines: the e2e "Browser" class stores Set-Cookie values and sends them back, follows redirects manually, and adds CSRF headers, so tests behave exactly like a browser.
  • Independent verification: push payloads are decrypted and VAPID signatures verified with Node's own crypto, not the app's code.
  • Reading the database directly: wrangler d1 execute --json proves tokens are encrypted and deletions are complete.
  • Driving the service worker: Chrome DevTools Protocol ServiceWorker.deliverPushMessage delivers a push to the real sw.js.
  • Recording speech: speechSynthesis is replaced with a recorder, so tests assert the exact sentence spoken.
  • Mocks that fail loudly: an early bug in the mock's control routes (a regex that did not match hyphens) silently ignored commands and produced 12 false failures; the test helper now throws if a mock command fails.
  • Read-only checks against a real Jira: old and new code compared side by side to prove a refactor changed nothing.
  • Measuring CPU: process.cpuUsage() around the hot paths, because local dev does not enforce Cloudflare's 10 ms limit.

What the tests cannot prove

  • Real push services delivering to real devices (verified manually with "Send a test push").
  • Exact CPU on Cloudflare's machines (check Metrics after deploying).
  • Every Jira configuration in the world (custom statuses, fields, permissions).
