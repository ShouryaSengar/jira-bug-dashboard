Loading "For You"

What happens when you open For You on the Cloud edition: from the browser, through the Worker, D1 and Atlassian's gateway, to Jira and back, with the numbers that keep it inside the free plan.

Inside the Worker

  1. Security gate: assertSameOrigin (GET passes), requireSession (hash the cookie, look it up, check expiry), a per-user rate limit.
  2. Who and where: activeSite() and settingsOf() in parallel.
  3. Token: accessToken() decrypts the stored access token, or refreshes it if it expires within 2 minutes.
  4. Severity fields: resolved once with /rest/api/3/field/search?query=Severity (small) and cached in user_settings. The full field list is avoided because big sites have thousands of fields, which would cost too much CPU to parse.
  5. Search: getMyBugs() from the shared core: assignee = currentUser() AND issuetype in ("Bug") AND (statusCategory != Done OR updated >= -90d) ORDER BY updated DESC, 100 per page, capped at 300 bugs.
  6. "Recently assigned": a second search assignee CHANGED TO currentUser() AFTER -7d; if a site rejects it, the created date is used instead.
  7. Latest activity: one D1 query for the last 300 non-trivial events, used to label each row ("Comment by Bob · 2h ago").
  8. Mapping: each raw Jira issue (often several KB of nested JSON) becomes a small MyBug with only what the screen needs.

Why api.atlassian.com and not the site URL

OAuth tokens are not accepted at https://yoursite.atlassian.net/rest/.... They must be sent to Atlassian's gateway: https://api.atlassian.com/ex/jira/{cloudId}/rest/api/3/.... The cloudId comes from accessible-resources at sign-in. Links shown to you still use the friendly site URL (/browse/ABC-1).

CPU: about 0.9 ms per 100 bugs for parsing and mapping, so 300 bugs is about 2.5 ms of the 10 ms limit.

In the browser afterwards

  • The result is cached in jbd.v1.fy.cache so the next visit renders instantly.
  • KPIs and charts are computed locally (analysis.ts), so clicking filters never calls the server again.
  • Clicking a bug calls GET /api/issue?key=… (issue + comments + changelog in parallel).
