Quality goals: security, speed, cost, reliability

Non-functional requirements (NFRs) are the "how well" of a system rather than the "what". Each goal below lists how it is met and how it was verified.

⏱ 8 min readGuide 9 of 47

GoalHow it is metVerified by

Stolen database ≠ stolen accessTokens AES-256-GCM encrypted with an external key; sessions stored as SHA-256 hashese2e reads D1 and checks for plaintext

Full detail: Threat model and defences.

Privacy

  • Data minimisation: no full issue contents stored, comments trimmed to 160 characters in history.
  • Retention: history 30 days; sessions 30 days (7 idle); IP hashes ~10 minutes; accounts erased 30 days after access ended.
  • User control: disconnect, delete account, revoke at Atlassian.
  • Atlassian's Personal Data Reporting API implemented and verified live.

See Privacy and the data life cycle.

Performance

OperationMeasured CPU (M1 Pro, V8)Free-plan limit
For You page: parse and map 100 issues~0.9 ms10 ms per invocation
Idle monitor check (300 tracked, 3000 seen ids)~0.4 ms
Monitor commit (serialise checkpoint)~0.5 ms
Classify 100 changelog entries~0.2 ms
Encrypt one Web Push message~0.45 ms

Network waiting does not count as CPU on Workers, so slow Jira responses do not break the limit. The frontend bundle is about 90 KiB uncompressed (26 KiB gzipped), with no framework.

Cost

  • Target: zero. Workers Free, D1 Free, GitHub Pages; no paid APIs; no AI services.
  • The free plan cannot bill you. Exceeding a limit returns errors until the daily reset (00:00 UTC), which the monitor treats as temporary.
  • Capacity on free: about 60 monitored users at a 5-minute interval, about 120 at 10 minutes. See The free tier and capacity maths.

Reliability

  • No lost events: the checkpoint advances only after a user's changes are fully processed; failed pushes stay pending and are retried for 6 hours.
  • No duplicates: every changelog item and comment id is recorded in seen.
  • Graceful overload: deferral instead of failure; exponential back-off with Retry-After.
  • Restart-safe: Workers hold no state; the Local server persists its state to disk atomically (write temp file, then rename).
  • Revocation-safe: an invalid_grant marks the grant revoked; the UI asks to reconnect; the monitor skips the user.

Maintainability

  • Shared core for both servers; one API contract; TypeScript strict mode everywhere.
  • Tests: ~29 local detection, 33 announcement rules, 82 cloud end-to-end, 34 browser, 16 unit (see How this app is tested).
  • Decisions recorded (Design decisions), schema in numbered migrations, these guides.

Usability and accessibility

  • Responsive down to 360 px wide; tables become cards on phones.
  • Keyboard shortcuts, focus outlines, ARIA labels, real buttons, reduced-motion support.
  • Five themes, including two dark ones.
